# خارطة تطوير بيلا روزا — الترتيب المقترح

آخر تحديث: 23 سبتمبر 2026. هذا الملف هو المرجع لترتيب العمل. كل مرحلة تُنفَّذ كاملة (واجهة + قاعدة بيانات +
صلاحيات + اختبار قبول) قبل الانتقال للتي بعدها، ولها ملف مهمة مستقل في `docs/` عند بدء تنفيذها.
الواجهة العاملة لا يُعاد بناؤها ولا تُغيَّر عشوائياً؛ كل تغيير بمهمة مكتوبة.

## القرارات المتخذة (23 سبتمبر 2026)

- الهدف: متجر إلكتروني كامل بدفع إلكتروني لفساتين وملابس الأطفال (إسبانية)، بيع فقط (لا تأجير). المقاسات بالأعمار.
- الأسلوب: نفس ملائم — GitHub Pages + Supabase، واجهة عربية بالكامل، مراحل صغيرة باختبارات قبول.
- الحسابات: GitHub `mohammedalseari-design` (ريبو `bellarosa`)، Supabase منظمة mulaem (خطة مجانية)، مشروع «بيلا روزا» منفصل عن ملائم.
- الدفع: المحل لديه سجل تجاري وحساب بنكي → تُفعَّل بوابة دفع سعودية في المرحلة 2؛ حتى ذلك الحين التحويل البنكي والدفع عند الاستلام.

## المرحلة 1 — الأساس (منجزة، ملف المهمة: `docs/TASK_PHASE1.md`)

قاعدة البيانات (منتجات/مقاسات/صور/تصنيفات/شحن/طلبات/أحداث/حركة مخزون) بصلاحيات RLS، إنشاء الطلب في السيرفر،
واجهة المتجر كاملة الرحلة (كتالوج → منتج → سلة → إتمام الطلب → صفحة الطلب → تتبع)، ولوحة الإدارة (لوحة، طلبات،
منتجات بمقاساتها وصورها، تصنيفات، شحن، إعدادات)، نبضة يومية ونسخة احتياطية.
**اختبار القبول:** 21 اختبار قاعدة بيانات + 25 اختبار متصفح (10 متجر، 12 لوحة، 3 دفع إلكتروني) — كلها ناجحة.

## المرحلة 0 (بعد النشر مباشرة، دقائق)

1. إنشاء أول حساب مدير من لوحة Supabase (الخطوات في `docs/SETUP.md`).
2. تفعيل GitHub Pages ورفع الشعار الحقيقي وبيانات المتجر (واتساب، البنك، الرقم الضريبي) من الإعدادات.
3. إضافة السر `SUPABASE_DB_URL` في GitHub ليعمل النسخ الاحتياطي الليلي.
4. استبدال المنتجات التجريبية بالمنتجات الحقيقية بصورها، ثم `scripts/clear-demo.sql`.

## المرحلة 2 — الدفع الإلكتروني (الكود جاهز ومنشور، ينتظر حساب البوابة — `docs/TASK_PHASE2_PAYMENT.md`)

بوابة دفع سعودية (المقترح Moyasar: مدى، بطاقات، Apple Pay، STC Pay) عبر نموذج الدفع في صفحة الطلب، والتحقق من
الدفع في السيرفر (Edge Function تستعلم من البوابة بالمفتاح السري وتقارن المبلغ بالطلب) — المبلغ لا يُؤخذ من
المتصفح أبداً. يبدأ بمفاتيح الاختبار ثم الحية.
**يحتاج قرارك:** فتح حساب في البوابة بالسجل التجاري والحساب البنكي، وإرسال المفتاح السري إلى أسرار Supabase (لا إلى المستودع).
**اختبار القبول:** طلب ببطاقة اختبار يتحول إلى «مدفوع» تلقائياً، ومحاولة دفع مبلغ مختلف تُرفض، وفشل الدفع يترك الطلب «بانتظار الدفع».

## المرحلة 3 — التشغيل اليومي

- إدارة الموظفين من اللوحة (Edge Function `admin-users` كما في ملائم) بدل لوحة Supabase.
- إشعار واتساب/SMS للزبونة عند تأكيد الطلب والشحن (يحتاج قرار: رقم واتساب رسمي للنظام أم رسائل يدوية بروابط جاهزة كما هو الآن).
- إلغاء تلقائي للطلبات غير المدفوعة إلكترونياً بعد مدة (يحرر المخزون المحجوز).
- كوبونات خصم (الحقل `discount` موجود في الطلب ومحجوز لذلك).

## المرحلة 4 — الفوترة والشحن

- فاتورة ضريبية مبسطة برمز QR (زاتكا) بدل الطباعة البسيطة الحالية — إن كان المحل مسجلاً في الضريبة.
- بوليصة شحن وتكامل مع شركة شحن (SMSA / أرامكس / تورود) ورقم تتبع يظهر للزبونة.

## المرحلة 5 — النمو

- النطاق الخاص: `bellarosa.com` و`.sa` و`.store` محجوزة (فحص GoDaddy 23 سبتمبر 2026)؛ المتاح: `bellarosa.shop` (Premium)،
  `bellarosa.boutique`، `bellaroza.com`، `bellarosaksa.com`، `bellarosa-shop.com`. نطاق `.sa` يُفحص في nic.sa مباشرة.
- SEO: الموقع صفحة واحدة، فصفحات المنتجات لا تُفهرس جيداً؛ الحل لاحقاً توليد صفحات ثابتة للمنتجات أو نطاق مع pre-render.
- بيكسل TikTok/Snap/Meta وتحليلات، تقييمات، حسابات زبونات، قائمة رغبات.

## ملاحظة على الجدوى

التكلفة التشغيلية الآن صفر (GitHub Pages مجاني، Supabase مجاني مع نبضة يومية). الحد الأعلى للخطة المجانية:
500MB قاعدة بيانات و1GB تخزين صور — الصور تُصغَّر في المتصفح قبل الرفع (أطول ضلع 1600px، JPEG) فتكفي لآلاف
المنتجات. الانتقال إلى Supabase Pro (25$/شهر) يصبح مبرراً عندما تكون هناك مبيعات فعلية تحتاج نسخاً احتياطية
لحظية بدل نسخة ليلية.

2. النطاق: أي اسم من المتاح أعلاه، أم الإبقاء على رابط GitHub Pages مؤقتاً.
3. رقم واتساب رسمي للمتجر (يظهر في الموقع ويستقبل الإيصالات والاستفسارات).
